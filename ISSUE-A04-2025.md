# A04:2025 – El outbox cifra eventos con AES-ECB y una clave fija

**Estado:** Vulnerabilidad intencional para demostración local.  
**Flujo afectado:** Registro de consumo anómalo → outbox PostgreSQL → publicación del evento.

## Ubicación

- `src/main/java/co/edu/univalle/fleetops/fuel/adapter/out/persistence/OutboxPayloadCipher.java`: clave fija incluida en el código y transformación AES/ECB.
- `OutboxJpaAdapter.java`: cifra el JSON antes de guardarlo en `outbox_events.payload` y lo descifra al leer eventos pendientes.

## Impacto

Cualquiera que lea el repositorio conoce la clave y puede descifrar los eventos almacenados. ECB también produce bloques iguales para bloques de texto iguales y no autentica el mensaje; un cambio en los datos cifrados no tiene una etiqueta criptográfica que permita detectar manipulación.

Esto afecta información del evento, como los identificadores de vehículo, conductor, ruta y asignación, el costo, los galones y la eficiencia.

## Reproducción local

1. Iniciar el servicio y PostgreSQL según el README.
2. Registrar un evento de consumo anómalo (un consumo más de 30 % por debajo del promedio del vehículo después de al menos dos mediciones).
3. Consultar la fila pendiente en PostgreSQL:

```sql
SELECT event_id, payload FROM outbox_events WHERE published_at IS NULL;
```

El campo contiene un sobre JSON con ciphertext Base64. La clave de demostración está en `OutboxPayloadCipher.java`; al descifrar AES-ECB se recupera el evento. El relay luego lo descifra y publica el JSON normal, de modo que el flujo funcional de la aplicación continúa.

## Corrección esperada

En la rama corregida, usar AES-GCM con nonce aleatorio único y una clave externa al código, por ejemplo desde un gestor de secretos. Al leer, verificar la etiqueta de autenticación; rechazar ciphertext alterado. No usar claves de demostración con datos reales.
